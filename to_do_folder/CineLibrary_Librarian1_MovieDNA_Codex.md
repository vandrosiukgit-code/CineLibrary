# CineLibrary — расширение агента «Библиотекарь 1»: Movie DNA / Tag Genome

> **Задание для Codex.** Разместить этот файл в `to_do_folder/` проекта. Он самодостаточен: удалённый ранее файл `CineLibrary_MovieLens_Integration_Spec.md` **не требуется**. Исходные CSV находятся в `tag_genom/`.

## 1. Цель

Расширить уже существующего агента **«Библиотекарь 1»** и его инструменты: при добавлении фильма в пользовательскую библиотеку, а также при однократном обогащении уже добавленных фильмов, прикреплять к фильму числовой **Movie DNA** (набор оценок MovieLens Tag Genome). Если готового генома нет — создавать **синтетический геном** из геномов ранее выпущенных фильмов-аналогов.

**Принципиальное разделение ответственности:**

- **ИИ-библиотекарь** только выбирает несколько кинематографически похожих фильмов по метаданным и описанию целевого фильма. Он **не генерирует 1128 чисел**, не рассчитывает веса и не записывает геном в БД.
- **Детерминированные скрипты** находят фильмы-аналоги, проверяют наличие оригинального Tag Genome, рассчитывают взвешенное среднее, качество/разброс, сохраняют результат, обслуживают импорт и повторные запуски.
- Существующая интеграция с **TMDB** остаётся главным источником карточек фильмов. Уже работающие обработка пользовательского списка на естественном языке, скрипты TMDB и другие агенты не переписываются.
- **Не использовать локальную ИИ-модель.** Использовать уже подключённую платную модель только для выбора аналогов, и только если оригинального генома нет.

## 2. Исходные файлы и точная структура MovieLens 25M

В `tag_genom/` лежат:

| Файл | Заголовок CSV | Значение |
|---|---|---|
| `links.csv` | `movieId,imdbId,tmdbId` | Связка MovieLens ID ↔ IMDb ID ↔ TMDB ID. `tmdbId` иногда пустой. |
| `genome-tags.csv` | `tagId,tag` | Числовой ID и текстовое название тега (английский). |
| `genome-scores.csv` | `movieId,tagId,relevance` | Значение релевантности тега конкретному фильму, обычно от 0 до 1. |

Связи:

```text
CineLibrary movie TMDB ID
    → links.csv.tmdbId
    → links.csv.movieId
    → genome-scores.csv.movieId
    → genome-scores.csv.tagId
    → genome-tags.csv.tagId
```

**Важно:** `links.csv` охватывает намного больше фильмов, чем `genome-scores.csv`. Наличие записи в `links.csv` **не означает**, что оригинальный геном существует. Проверять наличие **реальных строк** в `genome-scores.csv`. Не подменять пропуски нулями. Для MovieLens 25M доступен словарь из 1128 тегов; фактический состав проверять по локальному файлу.

Использовать нормализованное сравнение целочисленного TMDB ID. Не сопоставлять по одному только названию. Для предлагаемых ИИ аналогов разрешать поиск через существующий TMDB-инструмент по названию + году, с проверкой неоднозначностей, после чего переходить к ID.

### Пример записей (иллюстративный формат, не реальные значения)

```csv
# links.csv
movieId,imdbId,tmdbId
123,0123456,4567

# genome-tags.csv
tagId,tag
1,absurd

# genome-scores.csv
movieId,tagId,relevance
123,1,0.82
```

Строки `# ...` здесь только подписи к примерам, не содержимое настоящих CSV.

## 4. Новый функциональный сценарий

### A. Готовый оригинальный геном

1. Фильм уже идентифицирован в TMDB; получен TMDB ID.
2. Скрипт проверяет локально наличие готового Movie DNA для фильма.
3. Если нет — по `links.csv` и импортированным данным ищет **оригинальный** геном.
4. Если найден — сохраняет/привязывает значения к фильму, отмечает `source=original`, не вызывает ИИ.
5. При повторной синхронизации не дублирует и не пересчитывает запись.

### B. Оригинальный геном отсутствует

1. Скрипт предоставляет «Библиотекарю 1» краткие данные фильма из TMDB (название, год, жанры, описание, keywords при наличии).
2. ИИ возвращает **упорядоченный список из 5–10 предполагаемых похожих фильмов**, желательно с годами и, если способен достоверно определить, TMDB ID. Сходство учитывать по тематике, интонации, юмору, атмосфере, сюжету и стилю, а не только жанру. Не выдумывать ID.
3. Скрипт идентифицирует аналоги через TMDB/локальный индекс, отсекает дубликаты и неоднозначные соответствия.
4. Из аналогов допускаются **только фильмы с оригинальным геномом**. Синтетические геномы не выступают донорами, чтобы избежать накопления ошибок.
5. Для оставшихся аналогов скрипт определяет веса по рангу, рассчитывает каждый тег как нормализованное взвешенное среднее; дополнительные обращения к ИИ не нужны.
6. Сохраняет синтетический геном (`source=estimated`) и информацию о донорах, весах, версии алгоритма, моменте расчёта и показателях разброса.
7. Если надёжных аналогов недостаточно, **не создавать фиктивно точный геном**: зафиксировать статус `insufficient_analogs` и оставить фильм доступным в обычной библиотеке.

Вызов ИИ происходит **один раз на отсутствующий геном**, с ограничениями расходов и кэшем; допускается пакетная обработка нескольких фильмов, если она поддерживается текущим агентом.

### Пример минимального ответа ИИ

```json
{
  "target_tmdb_id": 123456,
  "analogs": [
    {"title": "Film A", "year": 2002},
    {"title": "Film B", "year": 1998},
    {"title": "Film C", "year": 2011},
    {"title": "Film D", "year": 2006},
    {"title": "Film E", "year": 1995}
  ]
}
```

Имена выше — заглушки формата. Использовать строго структурированный ответ; Codex подберёт schema/tool interface согласно существующей архитектуре.

## 5. Математика синтетического генома — без ИИ

Для каждого тега `t` и каждого допустимого донора `i` взять исходную релевантность `g[i,t]`. Веса определять **детерминированно** по рангу списка, например `raw_weight[i] = 1 / rank[i]`, после фильтрации перенормировать:

```text
weight[i] = raw_weight[i] / sum(raw_weight)
estimated[t] = sum(weight[i] * g[i,t])
```

Если у какого-то донора отсутствует значение отдельного тега, считать среднее только по донорам с известным значением и отдельно перенормировать веса для этого тега. **Не заменять пропуск 0.**

Оценка разброса по тегу:

```text
variance[t] = sum(weight[i] * (g[i,t] - estimated[t])^2)
```

В варианте с пропусками использовать перенормированные веса конкретного тега. `variance` — показатель согласия доноров, **не доказанная вероятность правильности предсказания**. Общий диагностический показатель можно агрегировать из дисперсий и числа пригодных доноров, чётко маркируя его как эвристику.

Не допускать выход `estimated[t]` за диапазон `[0, 1]`. Вынести схему весов, минимальное число доноров (например, 3), максимальное число доноров (например, 10) и версию алгоритма в настройки. Начальные числа — настраиваемые значения, а не научно установленный оптимум.

**Ограничение метода:** усреднение нескольких доноров может сглаживать яркие свойства нового фильма. Не обещать достоверности оригинального Tag Genome; сохранять информацию о синтетическом происхождении и возможность последующего перерасчёта.

## 6. Хранение и инструменты

Предпочтительна отдельная структура данных для Movie DNA, связанная с существующей записью фильма, а не добавление 1128 колонок в главную таблицу. Реальные имена, индексы и миграции выбрать по текущему стеку.

Хранить как минимум:

- Привязку к существующему фильму и нормализованный TMDB ID.
- Значения `tagId → relevance` и словарь тегов; исходные оригинальные числа без изменений.
- `source`: `original` / `estimated`.
- Для `estimated`: donor TMDB/MovieLens IDs, их ранги и итоговые веса, название и версия алгоритма, дата расчёта, число использованных доноров, диагностический разброс.
- Статус обработки: готово, отсутствует оригинал, недостаточно аналогов, ошибка, отложено.

Предоставить агенту минимальные инструменты/вызовы, соответствующие существующему механизму:

1. `get_movie_genome_status` — проверить наличие и источник.
2. `resolve_analog_genomes` — принять список аналогов, определить ID, вернуть подтверждённые оригинальные геномы/статусы.
3. `synthesize_and_save_genome` — вычислить и сохранить математически, без нового запроса к ИИ.
4. `get_movie_genome` — получить сохранённые значения и метаданные другим агентам.

Имена условны: **не создавать дублирующий framework**, а интегрировать операции в текущие инструменты. Проверять права/доступ и входные данные. Возможна одна комбинированная функция вместо нескольких.

## 7. Первоначальная загрузка и дальнейшая синхронизация

- Однократно импортировать/проиндексировать три CSV локально, **потоково** обрабатывать `genome-scores.csv` (сотни МБ), не загружая целиком в RAM.
- Не читать этот CSV заново при каждом фильме или запуске CineLibrary.
- Сначала **массово обогатить существующую библиотеку оригинальными геномами без ИИ**.
- Для оставшихся фильмов предусмотреть отдельный **управляемый запуск** синтетического заполнения: ограничение количества фильмов/вызовов, режим предварительного просмотра, отмена/продолжение, журнал расходов если платформа предоставляет usage.
- Для новых фильмов использовать тот же конвейер после нормальной TMDB-каталогизации. Сбой обогащения не должен блокировать добавление фильма.
- Повторные запуски идемпотентны. `original` никогда не перезаписывается `estimated`; при появлении оригинала можно заменить синтетику оригиналом, сохранив историю/происхождение по правилам проекта.
- Не обновлять синтетику автоматически на каждом старте; перерасчёт — отдельная управляемая операция.

## 8. Ограничения

- Не менять дизайн карточки, UI поиска, личные оценки, отзывы, теги впечатлений и логику рекомендательного агента в этой задаче.
- Не вводить локальные LLM/embeddings, новые платные сервисы или отдельного интеллектуального агента.
- Не отправлять CSV и весь каталог в платный AI API.
- Не использовать пользовательские оценки при вычислении **самих свойств фильма**.
- Не выдумывать совпадения TMDB ID и не использовать текстовую близость названия как единственный критерий идентификации.
- Сохранять оригинальные идентификаторы и теговые значения; учитывать отсутствие части фильмов и тегов.
- Проверить условия использования MovieLens/GroupLens до распространения данных в коммерческом продукте; не считать стороннее зеркало новой лицензией.

## 9. Проверка и критерии готовности

Проверить автоматизированно и на небольшой реальной выборке:

1. Фильм с оригинальным геномом — корректное сопоставление TMDB → MovieLens, импорт без ИИ.
2. Фильм без оригинального генома — ИИ создаёт **только список аналогов**; скрипты выполняют всё остальное.
3. Аналоги без генома, дубли, неоднозначные названия, пропущенные ID корректно отбрасываются.
4. Формула весов, нормализация, дисперсия и обработка пропусков проверены тестами.
5. Повторное выполнение не приводит к дублированию и повторным платным вызовам.
6. Пользовательская библиотека и остальные агенты продолжают работать как прежде.
7. Геном доступен через устойчивый интерфейс чтения для дальнейшего подключения к рекомендациям.

После реализации выдать отчёт: изменённые файлы, миграции, число фильмов с `original`/`estimated`/без генома, количество обращений к модели, способы запуска первоначального и повторного импорта, известные ограничения.
