# CineLibrary — техническое задание для Codex
## Продвинутый поиск, фильтрация и навигация по личной библиотеке

### Роль и задача
Ты — разработчик существующего приложения CineLibrary. Не создавай новое приложение. Изучи текущий код, структуру БД, API, компоненты каталога, карточку фильма, систему пользовательских оценок, тегов, отзывов и уже подключённый ИИ. Реализуй удобную расширенную навигацию по существующей библиотеке с минимальными изменениями архитектуры.

**Ключевое ограничение:** текущие функции, данные, оценки, отзывы, статусы просмотра, скачивания, список желаний и рекомендации должны продолжать работать. Не заменяй существующий ИИ и не подключай новые модели или сервисы без необходимости и согласования.

### Наблюдаемое состояние интерфейса
- На стартовом экране есть строка поиска по названию, актёру и режиссёру.
- Жанры выбираются из длинного одиночного выпадающего списка.
- Сортировка включает «Сначала новые», «Сначала старые», «По названию», «По моей оценке».
- Карточка фильма содержит год, несколько жанров, IMDb, режиссёра, актёров, статусы и блок «Мои впечатления»: звёздная оценка, теги впечатлений, текстовый комментарий.
- Встречаются теги «Тронул», «Рассмешил», «Достаточно одного просмотра», «Смотрелось легко».
- На карточке также видны статусы «Скачивается», «Просмотрен», «В списке желаний» и NEW. Уточни их точную семантику по коду: **не считай NEW статусом просмотра**.

## 1. Принципы UX

1. Сохрани быстрый поиск на главном экране; рядом размести кнопку «Фильтры» с количеством активных условий.
2. Часто используемые фильтры можно вынести в компактные чипы: «Жанры», «Годы», «Оценки», «Статус», «Впечатления».
3. Все дополнительные условия помести в боковую панель или адаптивное модальное окно «Расширенный поиск».
4. Выбранные условия показывай отдельными удаляемыми чипами над результатами; добавь «Сбросить всё».
5. Показывай количество найденных фильмов и информативное пустое состояние с предложением ослабить фильтры.
6. Сохраняй состояние поиска при открытии карточки и возврате в каталог: текст, фильтры, сортировка, позиция прокрутки. По возможности отражай фильтры в URL.
7. Обеспечь клавиатурную навигацию, адаптивность, читаемые подписи и отсутствие горизонтального переполнения.
8. Поиск должен обновляться быстро, с debounce для текстового ввода; избегай полного перезапроса каталога при каждом символе.

## 2. Поля расширенной фильтрации

### 2.1. Метаданные фильма
- Название: оригинальное и локализованное, поиск по части строки, без учёта регистра; при наличии инфраструктуры — устойчивый к опечаткам.
- Год выхода: от/до и готовые периоды (до 1980, 1980–1999, 2000–2009, 2010–2019, 2020+); периоды являются примерами, не жёстко зашитой схемой.
- Жанры: множественный выбор; режим «любой из выбранных» (OR) / «все выбранные» (AND), отдельный список исключений (NOT).
- Режиссёр, актёр: автодополнение по данным библиотеки; несколько значений с режимом ANY/ALL, где это осмысленно.
- Страна производства и язык оригинала: только если поля реально доступны в существующих метаданных; иначе отложить, не заполнять догадками.
- Продолжительность: интервалы до 90, 90–120, 120–150, более 150 минут, плюс произвольный диапазон — только при наличии данных.
- Тип произведения: фильм / сериал / мини-сериал / другое — **только если существующая модель данных различает эти сущности**.
- Франшиза/серия, студия, сценарист, композитор: необязательные фильтры второго этапа при наличии надёжных полей.

### 2.2. Рейтинги и история
- IMDb: диапазон, включая фильмы без рейтинга отдельным состоянием.
- Моя оценка: диапазон с учётом реальной шкалы приложения; отдельно «Не оценивал».
- Разница между моей оценкой и IMDb: «Оценил выше публики», «Оценил ниже публики», порог расхождения — только при корректной нормализации шкал.
- Дата добавления в библиотеку: диапазон.
- Дата просмотра и число повторных просмотров: только если эти данные уже существуют или пользователь явно согласует их сбор.
- Наличие текстового отзыва: есть / нет.
- Наличие личной оценки: есть / нет.

### 2.3. Состояния коллекции
- Просмотрен / не просмотрен / статус неизвестен (если модель допускает).
- В списке желаний / не в списке желаний.
- Скачивается / скачан / не скачан — только если эти состояния действительно поддерживаются текущей системой.
- Недавно добавлен: по реальной дате добавления, а не автоматически по значку NEW.
- Не смешивай независимые состояния: фильм может быть одновременно просмотрен и находиться в списке желаний, если текущая бизнес-логика это допускает.

### 2.4. Личные впечатления
- Множественный выбор существующих тегов.
- Режим «любой тег» / «все теги» / «исключить теги».
- Поиск по тексту собственного комментария.
- Фильтр «Без тегов».
- Фильтр «Есть отзыв, но нет оценки» и наоборот.
- Поиск по смыслу комментариев — **отдельный опциональный режим**, только если имеющийся ИИ/API поддерживает это без нежелательных расходов и изменения архитектуры.

## 3. Предложения по расширению тегов впечатлений

**Не добавляй автоматически все теги в БД.** Сначала проверь существующий справочник, дубли и способ хранения. Подготовь миграцию или конфигурацию с совместимостью; пользователь должен иметь возможность утвердить набор. Теги описывают **личную реакцию зрителя**, а не объективные характеристики фильма. Сохрани уже существующие теги.

| Категория | Предлагаемые теги |
|---|---|
| Эмоции | Тронул; Рассмешил; Вдохновил; Растрогал; Напугал; Разозлил; Оставил равнодушным; Вызвал тревогу |
| Интеллектуальная реакция | Заставил задуматься; Удивил; Открыл новую тему; Хочется обсудить; Неоднозначное впечатление |
| Темп и вовлечённость | Смотрелось легко; Держал в напряжении; Затянут; Скучно; Захватил с первых минут; Требует внимания |
| Сюжет и финал | Неожиданный финал; Предсказуемый сюжет; Сильная история; Слабый сценарий; Открытый финал понравился; Финал разочаровал |
| Персонажи и исполнение | Сильные персонажи; Убедительная игра; Героям не сопереживал; Запомнился персонаж |
| Эстетика | Красивая операторская работа; Атмосферный; Запоминающаяся музыка; Визуально впечатлил |
| Повторный просмотр | Хочу пересмотреть; Достаточно одного просмотра; Не досмотрел; Хочу продолжение |
| Рекомендация другим | Посоветовал бы; Не рекомендую; Для совместного просмотра |

**Правила качества тегов:**
- Не делай чрезмерно длинный плоский список: показывай категории, избранные/частые теги и поиск по тегам.
- Не смешивай взаимоисключающие варианты без явного решения пользователя.
- Предусмотри переименование/объединение дублей без потери связей с отзывами.
- Не подменяй пользовательские теги автоматически выводами ИИ.
- Отдельные технические поля (например, «не досмотрел», «хочу пересмотреть») лучше хранить как структурированные состояния, **если это предусмотрено архитектурой**; не дублируй их тегами без обоснования.

## 4. Логика комбинаций условий

Реализуй предсказуемую модель:
- Между разными группами фильтров — AND по умолчанию.
- Внутри группы с несколькими значениями — переключатель ANY (OR) / ALL (AND), если применимо.
- Исключения внутри группы — NOT.
- Диапазоны имеют включённые границы, если интерфейс не говорит иное.
- Значения NULL / «неизвестно» обрабатываются явно; отсутствие оценки не равно нулю.
- Не допускай некорректных комбинаций (например, нижняя граница года больше верхней).
- В сложном поиске поддержи группы условий `(A OR B) AND C`, **но не заставляй обычного пользователя строить логические выражения вручную**. Начни с понятных групп, сложный конструктор — отдельный этап.

### Примеры пользовательских комбинаций и ожидаемого результата

1. `жанры: детектив И комедия` + `год: 2010–2025` + `моя оценка: высокая` → фильмы, удовлетворяющие всем трём ограничениям.
2. `жанры: драма ИЛИ мелодрама` + `исключить: ужасы` + `IMDb ≥ 7` → пересечение жанровой группы с рейтингом, за исключением ужасов.
3. `режиссёр: выбранный` + `актёр: выбранный` → совместные работы из библиотеки.
4. `просмотрен` + `тег: Тронул ИЛИ Заставил задуматься` + `хочу пересмотреть` → эмоционально значимые фильмы для повторного просмотра.
5. `не просмотрен` + `в списке желаний` + `продолжительность ≤ 100 минут` → короткие кандидаты на вечер.
6. `моя оценка ≥ 8` + `IMDb < 7` → фильмы, которые пользователь любит больше широкой аудитории (если шкала оценки сопоставима).
7. `отзыв есть` + `оценки нет` → записи, требующие дополнения.
8. `жанр: фантастика` + `исключить тег: Скучно` + `сортировка: моя оценка ↓` → персональная подборка фантастики.
9. `год: до 2000` + `страна: выбранная` + `тег: Атмосферный` → историческая часть библиотеки с нужным впечатлением.
10. `текст: название или актёр` + `статус: просмотрен` + `сортировка: дата добавления ↓` → быстрый поиск среди просмотренного.

Все примеры — сценарии для проверки, а не утверждение, что указанные данные уже присутствуют в БД.

## 5. Сортировка

Сохрани текущие варианты и добавь, когда поля доступны:
- По IMDb: возрастание / убывание.
- По моей оценке: возрастание / убывание; фильмы без оценки помещай отдельно/в конец.
- По дате добавления: новые / старые.
- По году выхода: новые / старые.
- По продолжительности: короткие / длинные.
- По названию: А–Я / Я–А с учётом локали.
- По дате просмотра (если доступна).
- Случайный порядок с фиксированным seed на время сессии/выдачи, чтобы карточки не прыгали при пагинации.
- Вторичный стабильный ключ сортировки для равных значений.

## 6. Сохранённые поиски

Предусмотри возможность сохранить набор фильтров под собственным названием: «Любимые детективы», «Кино до 100 минут», «Хочу пересмотреть». Сохраняй **условия запроса**, а не статический список результатов: выдача должна обновляться вместе с библиотекой. Дай переименовывать, удалять и применять пресеты. На первом этапе допустимо локальное хранение, если приложение однопользовательское; если есть аккаунты и синхронизация — используй существующий серверный механизм.

## 7. Умный поиск (опционально, после базовых фильтров)

Отдельный переключаемый режим: пользователь пишет «Покажи непродолжительные детективы после 2015 года, которые я ещё не смотрел».

- Используй **уже подключённый** ИИ, не меняя модель и провайдера.
- ИИ должен возвращать **строго типизированный объект фильтров**, а не SQL, исполняемый код или произвольные команды.
- Валидируй объект по схеме и доступным значениям справочников; неизвестные условия явно показывай как неподдержанные.
- Показывай интерпретацию запроса в редактируемых чипах до/после применения.
- Саму фильтрацию выполняет обычный движок поиска; не отправляй весь каталог в модель без необходимости.
- Никаких скрытых записей в БД или изменения оценок/тегов по результату поискового запроса.
- При недоступности ИИ обычный поиск продолжает работать.
- Не отправляй личные отзывы во внешние сервисы без проверки действующих настроек приватности и согласия пользователя.

## 8. Реализация и производительность

1. Перед изменениями определи стек, хранилище, существующие эндпоинты, индексы, объём библиотеки, схему оценок и фактические поля метаданных.
2. Повторно используй текущие компоненты, сервисы и маршруты. Не вводи новый поисковый сервер для небольшой локальной библиотеки без измеренной необходимости.
3. Если каталог загружается целиком и невелик, допустима локальная фильтрация; при больших объёмах — серверная фильтрация, индексы и пагинация/виртуализация. Выбор обоснуй.
4. Текстовый поиск: сначала возможности текущей БД и существующего поискового механизма; полнотекстовые индексы или FTS — только при доказанной пользе.
5. Не делай запрос к ИИ при обычной фильтрации.
6. Учитывай связи «фильм ↔ жанры», «фильм ↔ актёры», «фильм ↔ пользовательские теги», не создавай дубликаты строк при JOIN.
7. Все параметры фильтров валидируй, запросы параметризуй, учитывай права доступа: пользователь видит только свою библиотеку и свои впечатления.
8. Для отсутствующих метаданных используй честное «неизвестно», а не вымышленные значения.
9. Миграции БД — обратимо или с безопасным планом отката; не удаляй существующие пользовательские данные.

## 9. План работы Codex

### Этап A — аудит (обязательно перед реализацией)
- Найди компоненты каталога, карточки фильма, существующих фильтров и сортировки.
- Опиши фактические поля БД и источники метаданных.
- Определи, какие предложенные фильтры реализуемы сразу, какие требуют миграций, какие пока невозможны.
- Проверь текущую семантику IMDb, личной оценки, NEW, статусов и тегов.
- Представь короткий план изменений по файлам, оценку сложности и риски. **Не переписывай рабочие подсистемы.**

### Этап B — основная реализация
1. Компактная панель фильтров, чипы, сброс, счётчик результатов.
2. Множественные жанры, годы, IMDb, личная оценка, статусы, существующие теги, наличие отзыва.
3. Корректная логика AND/OR/NOT и расширенная сортировка.
4. Сохранение состояния при переходе в карточку и обратно.
5. Автодополнение по режиссёрам/актёрам, если данные позволяют.

### Этап C — после согласования
- Новые теги и необходимые миграции.
- Сохранённые поиски.
- Дополнительные фильтры по странам, языкам, продолжительности и датам.
- Умный поиск через существующий ИИ.
- Конструктор сложных групп условий, если простых фильтров недостаточно.

## 10. Проверки и критерии приёмки

- Существующий поиск, сортировка и открытие карточек работают как раньше.
- Комбинации AND/OR/NOT возвращают корректные результаты; проверены тестами.
- Оценки IMDb и пользователя не смешиваются; NULL обрабатывается корректно.
- Фильтры по тегам работают на уже сохранённых отзывах.
- Изменения отзывов и тегов корректно отражаются в результатах после обновления данных.
- При возврате из карточки сохраняются фильтры и положение в списке.
- Фильтрация не вызывает ненужных запросов к ИИ.
- Длинные списки жанров/тегов удобны для выбора и доступны с клавиатуры.
- Проверены пустая библиотека, отсутствие рейтингов, неизвестные поля, большое число фильмов и мобильная ширина.
- Написаны тесты для движка фильтров и ключевых пользовательских сценариев.
- Все изменения перечислены по файлам, указаны выполненные проверки и оставшиеся ограничения.

## 11. Формат ответа Codex

Сначала дай:
1. Краткую карту текущей реализации.
2. Таблицу «фильтр → поле/источник → доступен сейчас / нужна миграция / нет данных».
3. Предлагаемый план работ по этапам и файлам.
4. Потенциальные конфликты с текущей логикой и оценку трудоёмкости.

После аудита приступай к безопасной реализации этапа B. **Не добавляй массово новые теги и не меняй ИИ-интеграцию до отдельного подтверждения.** В конце покажи итог, тесты и список отложенных возможностей.
