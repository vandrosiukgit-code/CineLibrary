# CineLibrary — простой многопользовательский режим

## Концептуальное задание для Codex

### 1. Цель

Расширить существующее домашнее приложение CineLibrary с одного пользователя до **нескольких независимых пользовательских аккаунтов**. Не превращать проект в коммерческую платформу, не создавать сложную инфраструктуру администрирования и не переписывать работающие механизмы без необходимости.

**Главный принцип:** каждый пользователь получает собственную историю кинематографического опыта, собственные рекомендации и собственные настройки приложения. При этом общие сведения о фильмах и программный инструментарий могут переиспользоваться.

Codex самостоятельно выбирает технические решения после изучения существующего проекта. Этот документ описывает желаемое поведение, а не предписывает стек, таблицы или способ аутентификации.

### 2. Аккаунты и переключение пользователей

- Предусмотреть создание нескольких локальных пользовательских аккаунтов для членов семьи.
- Каждый аккаунт имеет отображаемое имя и при желании аватар.
- Обеспечить понятное переключение активного пользователя из существующего интерфейса.
- При переключении должны одновременно переключаться библиотека, отзывы, рекомендации, настройки и состояние соответствующих пользовательских сервисов.
- Предусмотреть редактирование профиля и настроек аккаунта.
- Для домашнего сценария использовать простой вход, но не допускать случайного доступа к чужим ключам или изменениям. Если приложение доступно по сети, обеспечить адекватную защиту доступа.
- Не вводить регистрацию через внешние сервисы и ненужные роли пользователей.

### 3. Разделение общих и персональных данных

**Общие данные, которые целесообразно переиспользовать:**
- Базовые метаданные фильмов TMDB, идентификаторы и фильмографии.
- Оригинальные MovieLens Tag Genome и вычисленные Movie DNA, поскольку они описывают **сам фильм**, а не вкус конкретного зрителя.
- Общие скрипты, инструменты и механизмы каталогизации.

**Строго персональные данные:**
- Список действительно просмотренных фильмов.
- Личные оценки, отзывы, эмоциональные реакции и теги Movie DNA.
- Профиль вкуса и история рекомендаций.
- Сохранённые фильтры, настройки интерфейса и пользовательские предпочтения.
- Настройки интеллектуального API, Telegram-бота и монитора медиатеки.

**Критическое правило:** присутствие фильма в библиотеке одного пользователя не означает, что другой пользователь его смотрел. Персональные реакции и рекомендации не смешиваются.

### 4. Настройки API для каждого пользователя

В настройках аккаунта предусмотреть конфигурацию необходимых уже поддерживаемых внешних API и параметров интеллектуальной модели.

- Возможность использовать собственные ключи и настройки пользователя.
- Не ломать текущие подключения и инструменты агентов.
- Не показывать полные секретные ключи на экране и не включать их в обычные логи, экспорты или сообщения об ошибках.
- При отсутствии личного ключа приложение должно понятно сообщать о недоступной функции. Возможность общего семейного ключа — только как **явно выбранный и контролируемый** вариант владельца, без скрытого заимствования секретов другого пользователя.
- Ограничения и расходы на платный ИИ должны быть понятны для активного аккаунта; исключить незаметные повторные вызовы при переключении.

### 5. Telegram для каждого пользователя

Сохранить существующий сценарий: пользователь выбирает фильм, а **скрипт Telegram-бота** отправляет владельцу аккаунта структурированное сообщение с данными фильма и его номером. Это заявка на **ручное** скачивание, а не автоматическая загрузка.

- Предусмотреть индивидуальные настройки Telegram (токен бота и получатель / chat ID либо иной уже реализованный способ подключения).
- При отправке заявки использовать **настройки активного пользователя**, не отправляя сообщения в чужой чат.
- Использовать существующий скрипт и ранее согласованный формат информативных сообщений.
- Поддерживать одиночные и групповые заявки.
- Сохранять действующее различие между запросом загрузки и добавлением фильма в историю просмотров.
- Обеспечить проверку подключения и понятные сообщения об ошибках.
- Telegram не должен становиться механизмом входа в приложение, если это не требуется существующей архитектурой.

### 6. Индивидуальный монитор медиатеки

У каждого пользователя — **собственные настройки монитора медиатеки**, размещённые в уже существующей левой панели настроек:

- Одна или несколько папок с фильмами (если это разумно поддерживается существующим проектом).
- Включение и выключение мониторинга.
- Интервал проверки, ручная команда «Сканировать сейчас».
- Включение обхода вложенных папок.
- Статус последней проверки, доступность каталога и сообщения об ошибках.

Монитор работает с файлами и папками, включая обычные видеофайлы, ISO, DVD `VIDEO_TS` и Blu-ray `BDMV`. Структура диска считается одним физическим экземпляром фильма, а не множеством отдельных фильмов.

Сопоставлять обнаруженное с записью фильма, в первую очередь по существующему идентификатору вида `CL-000054`, присутствующему в имени файла или корневой папки. **До использования в многопользовательском режиме проверить уникальность и область действия CL-идентификатора.** Если идентификаторы уникальны только внутри аккаунта, одинаковый номер у двух пользователей не должен приводить к перекрёстной привязке файлов.

При обнаружении связанного экземпляра в карточке активного пользователя показывать «Доступен к просмотру», фактическое имя файла/папки и при необходимости формат. При удалении последней копии после успешной проверки эти сведения исчезают. Если папка или диск временно недоступны, не считать все фильмы удалёнными.

**Физическая медиатека и история просмотра независимы.** На диске могут находиться ещё не просмотренные фильмы; монитор не создаёт из них записи в каталоге просмотренных. Удаление физического файла никогда не удаляет оценку, отзыв или Movie DNA.

Если несколько аккаунтов используют одну физическую папку, допустить повторное использование результатов сканирования ради экономии ресурсов, **но не смешивать персональные статусы и связи с каталогами**.

### 7. Каталог и рекомендации

- Каждый пользователь видит свою историю просмотренных фильмов и только собственные оценки и отзывы.
- Рекомендательный агент использует профиль **текущего пользователя** и его пожелания из четырёх существующих карточек подбора.
- Общие Movie DNA можно использовать повторно без повторного платного расчёта для каждого аккаунта.
- Инструментарий остаётся общим для агентов, но запросы к личным данным всегда выполняются в контексте выбранного аккаунта.
- Не смешивать историю и рекомендации пользователей даже при совпадении названий и CL-номеров.

### 8. Переход с одного пользователя

Текущая версия CineLibrary рассчитана на одного человека. При внедрении необходимо:

1. Сохранить все имеющиеся фильмы, оценки, отзывы, теги, настройки и доступные связи с файлами.
2. Перенести существующие личные данные в **первый аккаунт** без потерь.
3. Сохранить работоспособность действующих сценариев Telegram, API и монитора медиатеки.
4. Не создавать пустой каталог вместо существующего после обновления.
5. Обеспечить безопасное повторное выполнение миграции или механизм восстановления из резервной копии.

### 9. Границы реализации

**Нужно:** простые аккаунты, разделение личных данных, настройки API и Telegram на пользователя, персональный монитор медиатеки, правильное переключение текущего пользователя.

**Не нужно:** коммерческие подписки, облачная синхронизация, социальные функции, общие рейтинги семьи, сложная ролевая модель, автоматическое скачивание, локальные ИИ-модели, новый Telegram-бот для каждого аккаунта без необходимости, отдельные копии общей базы фильмов для каждого пользователя.

Не изменять без причины существующие механизмы Movie DNA, TMDB, агентную архитектуру, карточки фильмов и интеллектуальный поиск.

### 10. Что поручается Codex

- Изучить текущую организацию пользовательских данных, настроек и общего каталога.
- Предложить минимальные изменения, достаточные для корректной изоляции аккаунтов.
- Реализовать переключение пользователя и соответствующие настройки в уже существующем интерфейсе.
- Адаптировать вызовы общих инструментов и фоновые задачи к пользовательскому контексту.
- Мигрировать текущего пользователя без потери данных.
- Проверить многопользовательские сценарии и предоставить отчёт о проведённых проверках.

### 11. Критерии приёмки

- Созданы два аккаунта; у каждого разные просмотренные фильмы, оценки и отзывы.
- Переключение аккаунтов корректно меняет каталог, настройки и рекомендации.
- Общее описание и Movie DNA одного фильма не дублируются без необходимости.
- Telegram-запрос каждого пользователя поступает только в указанный им чат.
- Разные пути мониторинга и интервалы проверки не конфликтуют.
- Совпадающие CL-номера двух аккаунтов не приводят к чужим файловым связям.
- Удаление фильма с диска меняет только его физическую доступность, не историю просмотра.
- Существующий пользователь после обновления сохранил данные и подключения.
- Секреты API и Telegram не раскрываются в интерфейсе и логах.
- Приложение остаётся простым и удобным для домашнего использования.

**Итоговая концепция:** несколько независимых зрителей используют одну CineLibrary с общими данными о кино и общими инструментами, но у каждого — свой кинематографический опыт, свои агенты в пользовательском контексте, настройки API, Telegram и монитор медиатеки.
