# Принципы проекта и решения для согласования

## Согласованные направления

- **История принадлежит зрителю.** Явное добавление просмотренного, просьба загрузить и обнаружение файла — три разных действия. Удаление файла сохраняет оценку и отзыв. Для связи домашнего экземпляра с фильмом уже используется имя с локальным номером `CL-`. [Правила проекта](../docs/AGENTS.md) · [Монитор](../to_do_folder/CineLibrary_Media_Library_Sync_Codex.md)
- **Movie DNA описывает фильм.** Реакция на свойство принадлежит зрителю. Оригинальный геном можно переиспользовать. Для оценки по аналогам ИИ предлагает названия, программа проверяет доноров и считает веса. Хранение источника позволяет объяснить уверенность. При нехватке данных каталог и подбор должны оставаться доступными. [Правила памяти](../docs/PROJECT_MEMORY_CONCEPT.md) · [Расчёт DNA](../to_do_folder/CineLibrary_Librarian1_MovieDNA_Codex.md)
- **Общие операции обслуживают несколько сценариев.** Библиотекарь отвечает за обогащение каталога, рекомендатель читает доступные сведения и подбирает фильмы. Telegram отправляет оформленную программой просьбу владельцу для ручной загрузки. Основная карточка и карточка фильма из фильмографии используют общий сервис заявок. [Общие инструменты](../to_do_folder/CineLibrary_Shared_Tools_Recommendation_Agent_Codex.md) · [Telegram](../to_do_folder/CineLibrary_Telegram_Request_Formatting_Codex.md)

## Решения владельца

1. **Согласовано. Заявка учитывается отдельно от желаний и файлов.** Если фильма ещё нет в каталоге, для имени заявки создаётся общая карточка со стабильным CL. Первоначально у неё `watched=False`, `inWishlist=False` и доступность `missing`. Заявка сохраняется после подтверждения Telegram. Физическая доступность определяется проверкой хранилища. [Сервис заявок](../backend/app/services/movie_download.py) · [Монитор](../to_do_folder/CineLibrary_Media_Library_Sync_Codex.md)

   **Два места для кнопки «Запросить загрузку».** Основная карточка фильма, когда файла нет на диске, и карточка фильма из фильмографии. Экран рекомендаций предназначен для просмотра результатов подбора. [Основная карточка](../to_do_folder/CineLibrary_Media_Library_Sync_Codex.md) · [Фильмография](../to_do_folder/CineLibrary_Actor_Filmography_Telegram_Codex.md)
2. **Всегда пять рекомендаций или пять по умолчанию?** UI передаёт выбранное количество, API допускает 1–10, а ТЗ требует пять объяснённых вариантов. Предложение — сохранить выбор количества и использовать пять по умолчанию. Постоянная пятёрка также возможна, но потребует согласованно изменить UI, контракт API и тесты. В обоих случаях остаются важны соблюдение запроса и объяснение результата. [Контракт](../backend/app/schemas/recommendations.py) · [Интерфейс](../frontend/src/App.tsx) · [ТЗ рекомендателя](../to_do_folder/CineLibrary_Shared_Tools_Recommendation_Agent_Codex.md)
3. **Когда переходить к семейным профилям и кому передать текущие данные?** Можно оставить ближайший выпуск однопользовательским или перенести историю, заявки и настройки в первый аккаунт до расширения личных функций. Предложение — назначить нынешнего владельца первым профилем, подтвердить состав переноса на копии, затем подключать персональные настройки и монитор. Отсрочка уменьшит ближайший объём работ, но добавит перенос новых личных данных позднее. [ТЗ аккаунтов](../to_do_folder/CineLibrary_Multiuser_Accounts_Codex.md) · [Текущая схема](../backend/app/sql/001_initial_schema.sql)
