# Как устроена CineLibrary

## От интерфейса до хранилища

Вход для пользователя — React-приложение. Оно обращается к FastAPI по HTTP. Точка сборки сервера — `backend/app/main.py`, функция `create_app`. При старте она инициализирует SQLite, подключает репозитории фильмов и персон, регистрирует маршруты и создаёт менеджеры фоновых заданий. Путь SQLite задаётся через `CINELIBRARY_MOVIE_DB`, по умолчанию используется `data/movies.db`. Обычный запуск может применить SQL-миграции. [Запуск](../README.md) · [Интерфейс](../frontend/src/App.tsx) · [Сборка сервера](../backend/app/main.py) · [Инициализация БД](../backend/app/database.py)

Заметка о состоянии версии 0.1.0 описывает ранний этап с JSON и будущим интерфейсом. В рабочем дереве уже есть React, SQLite и внешние клиенты. Для оценки текущей реализации используйте точки входа выше. [Историческая заметка](../docs/PROJECT_STATE.md)

## Где пока есть только основа

- **Movie DNA.** `MovieLensIndex.get_original(tmdb_id)` читает оригинальные теги через отдельный SQLite-индекс. `links.csv` связывает `tmdbId` с `movieId`, `genome-scores.csv` связывает `movieId` с `tagId` и `relevance`, `genome-tags.csv` содержит названия тегов. Оценка по аналогам доступна по явному запросу к «Библиотекарю 1». [Исходные CSV](../tag_genom/) · [Импорт и чтение](../backend/app/repositories/movielens.py)
- **Монитор медиатеки.** Таблица `movie_files` и генерация имени с локальным ID уже есть. В коде не найден сканер, который подтверждает наличие файлов, DVD/Blu-ray-папок или ISO, либо отличает недоступный диск от пустого. [Схема файлов](../backend/app/sql/001_initial_schema.sql) · [Генерация имени](../backend/app/services/telegram_delivery.py)
- **Аккаунты и размещение.** Первичный ключ личной записи — один `movie_id`, настройки Telegram и API имеют по одной строке, ключи API загружаются в окружение процесса. Менеджеры заданий создаются на процесс. Клиент каталога использует адрес на `127.0.0.1`. Изоляция семейных профилей и облачное развёртывание остаются планами. [Схема личных данных](../backend/app/sql/001_initial_schema.sql) · [Telegram](../backend/app/sql/008_telegram_delivery.sql) · [Настройки API](../backend/app/services/api_credentials.py) · [Задания](../backend/app/services/recommendation_jobs.py)

## Этап 1. Заявка и физическая доступность

Маршрут `/api/movies/download-requests/by-tmdb` проверен на успех, отказ и повтор после отказа. У существующих фильмов сохраняются желания, доступность, просмотр и оценка. Новая карточка сохраняет тот же CL при повторе. Отказ даёт HTTP 502, без записи о доставке. В браузере на 1680 × 1050 подтверждены видимая ошибка в предпросмотре и доступность кнопки для повторной попытки. Все 27 тестов backend прошли, линтер и сборка frontend завершились успешно. [Автоматические тесты](../backend/tests/test_movie_download.py)

Для дальнейших этапов нужны малая выборка CSV с известным результатом Movie DNA, данные двух профилей и временный каталог с разными носителями и ошибкой доступа. Клавиатурная навигация предпросмотра остаётся отдельным сценарием фильмографии. [Дорожная карта](ROADMAP.md)

Основная карточка и предпросмотр в фильмографии используют общий обработчик заявки. В браузере на демостенде «Интерстеллар» со статусом «На диске» показан без кнопки. У «Бегущего по лезвию 2049» со статусом «Нет на диске» кнопка оставалась доступной после отправки. Два последовательных нажатия дали два ответа 201. У «Прибытия» после ответа 502 отображалась ошибка, кнопка повтора была доступна. Статусы файлов сохранились. Галочки и групповая отправка удалены из интерфейса рекомендаций, результаты отображаются карточками фильмов. [Интерфейс](../frontend/src/App.tsx) · [Дорожная карта](ROADMAP.md)

Предпросмотр фильмографии примыкает к строке фильма. Короткая задержка переключения даёт перевести указатель на кнопку, а вход указателя или фокуса в карточку отменяет закрытие. В браузере на демостенде проверены переход от строки к кнопке, заявка с ответом 201 и переключение на соседний фильм. [Интерфейс](../frontend/src/App.tsx)

## Этап 3. Оригинальный Movie DNA

Запуск из `backend/` в PowerShell:

```powershell
..\.venv\Scripts\python.exe -m app.repositories.movielens import
..\.venv\Scripts\python.exe -m app.repositories.movielens lookup 862 --summary
```

Импорт создаёт `data/movielens.db` из локальных CSV. Повторный запуск собирает индекс заново и заменяет предыдущую версию после успешной записи. Для другого набора данных указывайте `import --csv-dir <папка> --dataset-version <версия>`. Уберите `--summary`, чтобы получить ID, имена и веса тегов.

Результат поиска различает отсутствующий индекс, отсутствие связи с TMDB, неоднозначную связь и запись MovieLens без оригинальных оценок. Единственная связь и найденные значения возвращаются с `source=original` и версией данных. Пропущенный тег отсутствует в результате, а исходный ноль сохраняется. Индекс используется отдельно от пользовательской SQLite. [Импорт и чтение](../backend/app/repositories/movielens.py) · [Проверки](../backend/tests/test_movielens.py)

Проба на 250 000 строк заняла 2,1 секунды. Полный импорт занял 105 секунд и создал индекс размером 345 МБ. В нём 62 316 связей, 1 128 тегов и 15 584 448 значений для 13 816 фильмов MovieLens. TMDB ID `862` дал 1 128 тегов, `31` найден в связях без оценок, `4912` имеет неоднозначную связь. Из 52 просмотренных фильмов каталога 47 имеют оригинальный геном, у двух есть связь без оценок, у трёх нет связи. Каталог проверен только для чтения. Все 43 теста backend прошли, вызовов модели было 0.

## Этап 4. Оценка Movie DNA

- `GET /api/agents/movie-librarian-1/movie-dna/{tmdb_id}` читает оригинал, сохранённую оценку или текущий статус. Оригинал имеет приоритет и может появиться после обновления индекса.
- `POST /api/agents/movie-librarian-1/movie-dna/{tmdb_id}/estimate` запускается для одного фильма из каталога. При отсутствии оригинала и сохранённого результата операция может выполнить один платный вызов для списка аналогов. Автоматический запуск при импорте фильмов отсутствует.
- Доноры подтверждаются в TMDB по названию и, при наличии, году. Из подходящих оригиналов берутся от 3 до 10 доноров. Вес исходно равен обратному рангу, а для каждого тега нормируется по донорам, у которых есть его значение. Разброс измеряет согласие доноров. Миграция 010 создаёт отдельную таблицу результатов. Параллельный запрос получает `in_progress`, просроченное резервирование можно заменить через 30 минут.
- На временной БД и полном локальном индексе три заранее выбранных оригинала дали 1 128 оценок тегов. Вызов подменной модели был один, повтор вернул сохранённый ответ. Платных вызовов было 0. Схема рабочей базы применится при обычном запуске backend.
- Технические сведения о Movie DNA доступны Codex через API. В ответе `GET` поле `analogs` содержит предложения Gemini и результаты их проверки, `donors` содержит принятых доноров и веса. В прежних оценках может быть доступен только список принятых доноров.
- Для списка аналогов используется компактный JSON и лимит 4 096 токенов на вывод. Если ответ оборвался, схема проверяет полностью полученные записи. При достаточном числе доноров расчёт сохраняется с пометкой `partial`, при нехватке сохраняется `insufficient_analogs`. Подбор проверен на подмене Gemini и TMDB. Реальный ответ с новым лимитом ещё предстоит проверить.
